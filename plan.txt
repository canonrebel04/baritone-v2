Severity: High
Description: In several hashCode() implementations, `BetterBlockPos.longHash(x, y, z)` (which returns a packed 64-bit coordinate representation) is cast directly to `(int)`. This truncates the upper 32 bits, which contains the X coordinate, meaning coordinates differing only in their X coordinate will produce identical hash values before any further multiplication. This causes severe hash collisions when storing these objects in HashMaps.
Reproduction: Create two `GoalBlock` objects with coordinates (100, 50, 50) and (200, 50, 50). Calling `hashCode()` will yield the exact same result because the `(int)` cast removes the X-coordinate bits.
Fix: Use `Long.hashCode(BetterBlockPos.longHash(x, y, z))` instead of `(int) BetterBlockPos.longHash(x, y, z)`.
