- **Severity:** Critical
- **Bug Type:** Logic Errors
- **Description:** Casting the 64-bit result of `BetterBlockPos.longHash(x, y, z)` to `(int)` before utilizing it as a hash code truncates the upper 32 bits. Because the X coordinate is often encoded in the upper bits of the long hash, this truncation causes completely different coordinates to produce identical hash codes, resulting in severe hash collisions when storing path nodes or goals in collections.
- **Reproduction:** Insert multiple `PathNode` objects with wildly different X coordinates but identical Y and Z coordinates into a `HashMap` or `HashSet`. The hash codes will collide, dramatically degrading performance from O(1) to O(N) or causing logical issues if equality relies implicitly on hashes.
- **Fix:** Replace `(int) BetterBlockPos.longHash(...)` with `Long.hashCode(BetterBlockPos.longHash(...))` to correctly mix the upper and lower 32 bits into a 32-bit int hash code.
